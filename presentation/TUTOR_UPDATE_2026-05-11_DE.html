User-Flow live

Vom Hass-Kommentar zur Strafanzeige in 4 Schritten

  1. Belästigung dokumentieren — Text einfügen, URL, oder Screenshot hochladen (OCR via Tesseract → OpenAI Vision)
  2. Klassifizierung — gpt-4o-mini mit Pydantic Structured Outputs liest 16 Kategorien, Severity, Paragraphen
  3. Fall erweitern — weitere Belege, Kontext, Verfasser:innen — auto-syncs zu Backend
  4. Strafanzeige erstellen — PDF mit Briefkopf, Belegen, KI-Bewertung → Polizei

Architektur

Eine Plattform, eine Rechnung, Frankfurt-Region

Migration auf Vercel

Railway-Trial lief aus → komplette Backend-Migration auf Vercel Fluid Compute (Python 3.12). Frontend + Backend + DB jetzt bei einem Anbieter, Frankfurt-Region für DSGVO.

  • Frontend: Vercel Static (Vite SPA)
  • Backend: Vercel Python Function via api/proxy.py
  • DB: Neon Postgres (Marketplace-Integration)
  • OCR-Fallback: OpenAI Vision (gpt-4o-mini) wenn Tesseract fehlt

Routing-Trick

// vercel.json "rewrites": [ { "source": "/api/(.*)", "destination": "/api/proxy?_p=$1" } ] # api/proxy.py qs = scope["query_string"] captured = parse(qs).get("_p") scope["path"] = "/api/" + captured await fastapi_app(scope, receive, send)

Path geht via Query-Param durch — ASGI-Shim restored ihn, damit FastAPIs /api/*-Routen matchen.

Zweiter KI-Layer

Nach n Belegen läuft analyze_case_legally(case) — produziert: rechtliche Bewertung (DE+EN), Eskalationsrisiko mit Begründung, stärkste Vorwürfe mit Strength-Score, priorisierte Handlungsempfehlungen mit Deadlines. Eingebettet in das Strafanzeige-PDF.

Beweissicherung

SHA-256 + browser-side Verifier

Jeder Beleg bekommt einen SHA-256-Hash über den exakten Inhalt zum Erfassungszeitpunkt. UTC-Timestamp, archive.org-Backup bei Scrape, alles im PDF.

Neu: Browser-Verifier — Polizei oder Anwält:in kann den Originalinhalt in SafeVoice einfügen, der Browser rechnet via Web Crypto API den Hash und vergleicht. Kein Netzwerk-Roundtrip, kein Vertrauen in unseren Server nötig.

„Du musst damit nichts tun; er liegt deinem Bericht bei." — Erklärtext in der UI
async function sha256Hex(text) { const enc = new TextEncoder().encode(text) const buf = await crypto.subtle .digest('SHA-256', enc) return Array.from(new Uint8Array(buf)) .map(b => b.toString(16).padStart(2,'0')) .join('') }

Gleicher Algorithmus wie Backend (hashlib.sha256) → bit-identische Ergebnisse → unabhängig prüfbar.

SafeVoice · Tutor-Update Folie 6 / 10
Das Deliverable

Strafanzeige als ein PDF, lesbar in 3 Sekunden

Struktur

  1. Briefkopf-Masthead — Titel + Fall-ID in Monospace rechts
  2. Übersichts-Karte — Anzeigeerstatter:in · Schweregrad · Vorfälle (mit kritisch-Count) · Paragraphen — Polizei liest das in 3 Sekunden
  3. Förmliche Strafanzeige — Sender-Block, Sachverhalt, Tatzeit/Tatort, Kontext
  4. Beweismittel — nummerierte Exhibit-Karten mit farbcodiertem Severity-Punkt, kursivem Zitat, Klassifizierung, §-Liste, SHA-256-Footer
  5. KI-gestützte Bewertung — typografisch abgesetzt (Tracked-Caps + Disclaimer) als Signal: das ist die KI, nicht das Opfer
  6. Seitenfußzeile — Fall-ID + Datum + Seitenzahl, 30 mm linker Rand für Lochung, dezente ✂-Falzmarke
Aktueller Stand

~9 KB

pro Strafanzeige-PDF (vorher ~3,5 KB ohne Übersicht und KI)

Sprachen

DE + EN, gleicher Code-Pfad, Helvetica + Times + Courier — keine System-Fonts, läuft auf Vercel ohne Extra-Setup

Generierung

ReportLab, 5–15 s (LLM-Bewertung wird inline berechnet). UI zeigt Spinner + „PDF wird erstellt…" während des Builds

UX-Entscheidungen

Trauma-bewusst statt motivierend

Was wir gestrichen haben

  • Pulsierende Critical-Badge — wirkte panisch auf einem Tool für Stress-Situationen
  • Kampf-Metaphern — „dich wehren" → „Du musst das nicht hinnehmen — und du musst es auch nicht alleine durchstehen"
  • Engineering-Jargon — „Resend-Integration geplant" → „E-Mail-Versand ist in der Beta noch nicht aktiv"
  • Marketing-Deutsch — DSGVO-Ansatz → DSGVO-konform; „right to justice" → „right to do something about it"
  • Login-Pflicht — anonymous-first ist DSGVO-stärker und niedrigschwelliger

Was wir hinzugefügt haben

  • Quick-Pick Empfänger — 3 große Karten statt 30-Eintrag-Dropdown
  • Geteilter Sender-Form über Vorschau- und Senden-Tab (kein Doppel-Ausfüllen)
  • Explizites Speichern statt Auto-Debounce (kein wackeliges Gefühl)
  • Post-Download Nächste-Schritte — Onlinewache oder Persönlich oder HateAid
  • JSON-Export/Import für Fälle — Nutzer:innen besitzen ihre Daten
  • Auto-Resync wenn lokale + Backend-Belege divergieren
