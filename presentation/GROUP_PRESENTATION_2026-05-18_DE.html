Drei Gründe, warum die meisten Fälle versanden:

  1. Betroffene wissen nicht, welche §§ einschlägig sind — Beleidigung, Bedrohung, Volksverhetzung, Stalking, Doxxing: 16 Tatbestände in DE

Die Lösung

Belästigung dokumentieren, KI klassifiziert, Strafanzeige fertig.

SafeVoice ist ein kontrollierter Beweis-zu-Aktion-Workflow. Kein Chat-Bot. Kein generisches LLM-Tool. Ein Werkzeug, das sich auf einen konkreten Job konzentriert: Online-Hass dokumentieren und in eine gerichtsverwertbare Strafanzeige übersetzen.

Text, URL oder Screenshot — 10 Sekunden

SCHRITT 3

Beweis gesichert

SCHRITT 4

Strafanzeige-PDF

A4, mit KI-Bewertung — 1 Klick

Anonym im Browser. Kein Konto. Kein Tracking. DSGVO-by-design.

Klassifizierung

Ein LLM-Call, ein Schema — keine Halluzination.

OpenAI gpt-4o-mini mit Pydantic Structured Outputs. 16 Kategorien als Python-Enum — das Modell kann keine Kategorie und keinen §-Paragraph erfinden, weil das Schema serverseitig erzwungen wird.

Few-Shot-Prompt mit:

  • Idiom-False-Positive — „Das bringt mich um" → low
  • Obfuscation — „du H*re" → kritisch trotz Sternchen
  • Rechtsextremer Code — „1488" → §130 Volksverhetzung
  • Doxxing — Adresse + Telefon gepostet → §126a/§238
  • victim_context-Regeln — Ex-Partner → §238 Stalking

Kein silent fallback — wenn das Modell unsicher ist, gibt es 503 zurück. Eine schwache Regex-Klassifizierung wäre für eine Strafanzeige schlechter als keine.

class ClassificationResult(BaseModel): severity: Severity # low | medium | high | critical categories: list[Category] # enum, 16 Werte confidence: float # 0–1 requires_immediate_action: bool summary: str # EN summary_de: str # DE applicable_laws: list[GermanLaw] potential_consequences: str potential_consequences_de: str

client.chat.completions.parse(
  model="gpt-4o-mini",
  response_format=ClassificationResult,
  messages=[…])

Zweiter KI-Layer

Vom Einzelbeleg zur Fallanalyse.

Ein zweiter Prompt-Pass fasst alle Belege + den vom Opfer beigesteuerten Kontext zu einer fallweiten juristischen Einschätzung zusammen. Das ist, was die Polizei lesen kann.

Was die KI ausgibt

  • Rechtliche Bewertung — Freitext-Absatz mit Begründung, DE + EN
  • Eskalationsrisiko — low/medium/high mit Begründung
  • Stärkste Vorwürfe — §§ mit Strength-Score (strong/medium/weak)
  • Nächste Schritte — priorisiert mit Deadlines (24 h / 7 d / when_ready)
Beispiel-Ausgabe (Case mit 4 Belegen)

„Die Aussagen sind beleidigend und drohend, was sowohl nach § 185 StGB als auch nach § 241 StGB strafbar ist. Die Schwere der Drohung in der letzten Nachricht ist kritisch und erfordert sofortige Maßnahmen."

Eskalationsrisiko: HIGH — „Die Drohung mit Gewalt könnte zu einer weiteren Eskalation führen."

Eingebettet im Strafanzeige-PDF mit klarem Disclaimer — typografisch abgesetzt, damit Polizist:in sofort erkennt: das ist die KI, nicht das Opfer.

Beweissicherung

SHA-256 + Archiv + Browser-Verifier.

Jeder Beleg bekommt einen SHA-256-Hash über den exakten Inhalt zum Erfassungszeitpunkt. Das ist ein 64-stelliger Fingerabdruck — verändert sich ein einziges Zeichen, ändert sich der Hash komplett.

Zusätzlich:

  • UTC-Timestamp mit Zeitzone (juristisch erforderlich)
  • archive.org-Backup-Link (bei URL-Scrape)
  • Hash-Chain zwischen Belegen — Manipulation eines Belegs invalidiert die ganze Kette

Neu: Browser-Verifier. Polizei oder Anwält:in kann den Originalinhalt einfügen und der Browser rechnet via Web Crypto API den Hash live — kein Vertrauen in unseren Server nötig.

// Im PDF sha256:3a11c1c3813f43e8d7b9dbda0dfbc571bd 362bf346c3d4412975d91475571c2a // In SafeVoice (Browser) const hash = await sha256Hex(originalText) // → derselbe Hash → unverändert ✓ // Im Terminal (jeder kann es) $ shasum -a 256 evidence.txt 3a11c1c3813f43e8d7b9d... // Drei-Wege-Verifikation. Police-grade.

DSGVO-by-design

  • Anonymous-first — Standardpfad braucht kein Konto, kein E-Mail, kein Tracking
  • Datenminimierung (Art. 5) — wir speichern nur, was für die Strafanzeige nötig ist
  • Lokale Datenhoheit — Fälle leben primär in localStorage des Nutzers, JSON-Export für eigenes Backup
  • Recht auf Löschung (Art. 17) — eingebaut, sofortige Hard-Delete-Option
  • Recht auf Auskunft (Art. 20) — JSON-Export aller eigenen Daten
  • Frankfurt-Region — Backend + DB in DE-Region (Neon eu-central im Pilot-Migrations-Plan)
  • SHA-256 + archive.org für unabhängige Beweis-Verifikation

Impressum + Datenschutzerklärung sind Vorab-Versionen, vor Live-Gang anwaltlich zu prüfen.

Warum LLM, warum jetzt

Warum funktioniert ein LLM hier, wo regelbasierte Systeme scheitern?

Was Sprache hier schwierig macht

  • Idiome — „Das bringt mich um vor Lachen" ist keine Bedrohung
  • Obfuscation — „H*re", „k!ll yourself", Stern-Maskierung, Leetspeak
  • Codes — 1488, 88, „14 words" — rechtsextremer Subtext, der ohne Wissen unsichtbar bleibt
  • Kontext-Sensitivität — gleicher Satz ist Beleidigung (§185) oder Bedrohung (§241), je nachdem wer es schreibt (Ex-Partner → Stalking § 238)
  • Mehrsprachigkeit — DE, EN, TR, AR im selben Fall

Wie wir es zuverlässig machen

  1. Schema enforcement — Pydantic Structured Outputs. Model kann nichts erfinden.
  2. Few-Shot mit Gegenbeispielen — Idiome, Obfuscations, victim_context-Regeln im System-Prompt
  3. Kein Silent-Fallback — 503 statt schwacher Regex-Klassifizierung
  4. Zweiter Layer für Fall-Ebene — kein Einzelbeleg trifft alleine die Entscheidung
  5. SHA-256 + Hash-Verifier — Polizei muss uns nicht vertrauen
