The Problem

Online hate is daily — and mostly without consequences.

Legal consultation — what most victims simply can't afford

Three reasons why most cases disappear:

  1. Victims don't know which laws apply — insult, threat, incitement, stalking, doxxing: 16 statutory offenses in the German criminal code alone.
  2. Evidence disappears — platforms delete posts, accounts get suspended.
  3. Filing a complaint is paperwork — facts, timing, location, statute list, addresses. Hours of work, often at the victim's psychological limit.

SafeVoice · KingZizis Demo 05 / 17
Classification

One LLM call. One schema. No hallucination.

OpenAI gpt-4o-mini with Pydantic Structured Outputs. 16 categories as a Python enum — the model can not invent a category or a statute, because the schema is enforced server-side.

Few-shot prompt with:

  • Idiom false-positive — "that's killing me" → low
  • Obfuscation — "you wh*re" → critical despite asterisk
  • Far-right code — "1488" → § 130 (incitement)
  • Doxxing — address + phone → § 126a / § 238
  • victim_context rules — ex-partner → § 238 (stalking)

No silent fallback. Low confidence → 503. A weak regex classification would be worse than none for a criminal complaint.

class ClassificationResult(BaseModel): severity: Severity # low|medium|high|critical categories: list[Category] # enum, 16 values confidence: float # 0–1 requires_immediate_action: bool summary: str # EN summary_de: str # DE applicable_laws: list[GermanLaw] potential_consequences: str potential_consequences_de: str
client.chat.completions.parse( model="gpt-4o-mini", response_format=ClassificationResult, messages=[...])
SafeVoice · Classification 06 / 17
Second AI Layer

From single piece of evidence to case-level analysis.

A second prompt pass combines all pieces of evidence + the victim-supplied context into one case-wide legal assessment. This is what the police read.

What the AI outputs

  • Legal assessment — free-text paragraph with reasoning, DE + EN
  • Escalation risk — low / medium / high with rationale
  • Strongest charges — statutes with strength scores
  • Next steps — prioritized with deadlines (24 h / 7 d / when_ready)
Sample output · case with 4 pieces of evidence

"The statements are insulting and threatening, which is punishable under both § 185 StGB and § 241 StGB. The severity of the threat in the last message is critical and requires immediate action."

Escalation risk HIGH

"The threat of violence could lead to further escalation."

Embedded in the complaint PDF with a clear disclaimer — typographically set apart so the officer immediately knows: this is the AI, not the victim.

SafeVoice · Second AI Layer 07 / 17
Iterations & Learnings

What we threw away until it worked.

Six hard pivots. Each one an admission: "the first idea was wrong."

Pivot 1 · Classification

Regex + keyword list + 3-tier fallback
→ gpt-4o-mini with Pydantic Structured Outputs

Why: regex flagged "that's killing me" as § 241. False-positive rate was unacceptable.

Pivot 2 · Model selection

Claude (Anthropic) + OpenAI in parallel
→ gpt-4o-mini only · one-provider stack

Tested: gpt-4o-mini vs gpt-4o vs gpt-5 (hyperparam sweep). gpt-5 marginally better on edge cases, but 8× more expensive + slower. gpt-4o-mini = best cost/quality ratio.

Pivot 3 · Prompt engineering

Minimalist prompt (v1)
→ Few-shot with chain-of-thought (v2)

Eval (35 cases): 66 % → 86 % accuracy (+20 pp). Added counter-examples for idioms, obfuscation, victim_context.

Pivot 4 · UX architecture

Login-first · user account · email verification
→ Anonymous-first · localStorage · no account

Why: stalking victims shouldn't have to create an account that can later be used against them. GDPR data minimization. Account = bonus, not requirement.

Pivot 5 · Hosting

Railway · Docker · always-on
→ Vercel Functions · Fluid Compute · FRA

Effect: $20/mo fixed → $0–$3/mo at expected volume. Cold start < 200 ms via Fluid Compute. One platform = one bill.

Pivot 6 · OCR (decided today)

Tesseract + Vision fallback
→ Vision-only (gpt-4o-mini)

Why: Tesseract never ran on Vercel. Vision additionally returns sender_handle + platform_hint. Dev = prod. 200 fewer lines of code.

SafeVoice · Iterations & Learnings 08 / 17
DB Architecture · Before / After

From a user-centric to a case-centric schema.

The UX pivot "anonymous-first" forced a DB pivot. user_id stopped being required and became optional.

Before · Login-first (v1)

users id PK email UNIQUE NOT NULL password_hash created_at cases id PK user_id FK → users.id # required title context ... evidence id PK case_id FK → cases.id user_id FK → users.id # redundant ...

Problem: victim without an account = no case. Email verification as a barrier for someone in crisis. Duplicate FKs.

Today · Anonymous-first (v2)

cases id PK user_id FK → users.id NULL # optional! anonymous_token UNIQUE # browser-local title, context, severity evidence id PK case_id FK text, image_bytes sha256_hash, archive_url classification_json # Pydantic SO legal_analysis # 2nd AI layer case_id FK assessment, escalation_risk applicable_laws users # only for power features id, email, password_hash

Today 10 tables. Cases can exist without a user — purely browser-local. Login = optional upgrade path for NGOs / lawyers.

SafeVoice · Cost 10 / 17
Evidence preservation

SHA-256. archive.org. Browser verifier.

Each piece of evidence gets a SHA-256 hash over the exact content at capture time — a 64-character fingerprint. Change a single character and the hash changes completely.

Additionally:

  • UTC timestamp with timezone (legally required)
  • archive.org backup link (when scraping a URL)
  • Hash chain between pieces of evidence — tampering with one invalidates the chain

NEW  Browser verifier. Police or lawyer pastes the original content; the browser computes the hash live via the Web Crypto API — no trust in our server required.

// In the PDF sha256:3a11c1c3813f43e8d7b9dbda0dfbc571bd 362bf346c3d4412975d91475571c2a // In SafeVoice (browser) const hash = await sha256Hex(originalText) // → same hash → unchanged ✓ // In the terminal (anyone can do it) $ shasum -a 256 evidence.txt 3a11c1c3813f43e8d7b9d... // Three-way verification. Police-grade.

SafeVoice · Tech & GDPR 13 / 17
Why an LLM, why now

Why does an LLM work where rule-based systems fail?

What makes the language hard

  • Idioms — "you're killing me" is not a threat
  • Obfuscation — "wh*re", "k!ll yourself", leetspeak
  • Codes — 1488, 88, "14 words" — far-right subtext
  • Context sensitivity — same sentence: § 185 or § 238 — depending on sender
  • Multilingual — DE, EN, TR, AR in the same case

How we make it reliable

  1. Schema enforcement — Pydantic Structured Outputs. Model cannot invent.
  2. Few-shot with counter-examples — idioms, obfuscation, victim_context rules
  3. No silent fallback — 503 instead of a weak regex guess
  4. Second layer at case level — no single piece of evidence decides alone
  5. SHA-256 + hash verifier — police don't have to trust us
Result

27 real-world test scenarios (DE/EN/TR/AR/ES) · 0 failures · 0 false positives on idioms · 0 invented statutes.

FAQ · also live on safevoice.app/faq

Six questions we always get asked.

1 · Is this legally binding evidence?

The PDF itself isn't a court verdict — it's a structured complaint document. The SHA-256 hash + archive.org backup + UTC timestamp make the underlying screenshot forensically verifiable. Police and prosecutors can use it directly.

2 · Can the AI hallucinate a wrong law (§ StGB)?

No. The 16 categories are a Pydantic enum, enforced server-side via OpenAI Structured Outputs. The model literally cannot return a value outside the enum. Confidence scores below 0.7 are flagged for human review.

3 · What happens to my data?

Anonymous-first: no account needed, everything in browser localStorage by default. Server-side: only what's actively being processed (Vercel Functions Frankfurt, no logs of content). GDPR Art. 25 by design.

4 · Why open source?

Victims of digital violence shouldn't have to trust a black box. NGOs (HateAid, neue deutsche medienmacher*innen) need to be able to audit and self-host. And: prosecutors can verify our hash-chain logic line by line.

5 · What about false positives?

86 % accuracy means 14 % needs review. The PDF always shows confidence + reasoning per classification. A human (victim or NGO) confirms before filing. We replace 4 hours of manual work, not the human judgment call.

6 · Who pays for this?

Free for victims, forever. NGO/government pilots cover infra ($90/mo at 10k cases). Funding application track: Prototype Fund, Schöpflin, Bertelsmann. Goal: pilot with HateAid in Q3 2026.
