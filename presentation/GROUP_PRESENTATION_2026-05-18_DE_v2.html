Anwaltsberatung — was viele Betroffene sich nicht leisten können

Drei Gründe, warum die meisten Fälle versanden:

  1. Betroffene wissen nicht, welche §§ einschlägig sind — Beleidigung, Bedrohung, Volksverhetzung, Stalking, Doxxing: 16 Tatbestände allein im StGB.
  2. Beweise verschwinden — Plattformen löschen Posts, Accounts werden gesperrt.
  3. Strafanzeige zu erstatten ist Papierkram — Sachverhalt, Tatzeit, Tatort, §§, Anschriften. Stunden Arbeit, oft am psychischen Limit.

Die Lösung

Belästigung dokumentieren. KI klassifiziert. Strafanzeige fertig.

Klassifizierung

Ein LLM-Call. Ein Schema. Keine Halluzination.

OpenAI gpt-4o-mini mit Pydantic Structured Outputs. 16 Kategorien als Python-Enum — das Modell kann keine Kategorie und keinen §-Paragraph erfinden, weil das Schema serverseitig erzwungen wird.

Few-Shot-Prompt mit:

  • Idiom-False-Positive — „Das bringt mich um" → low
  • Obfuscation — „du H*re" → kritisch trotz Sternchen
  • Rechtsextremer Code — „1488" → § 130 Volksverhetzung
  • Doxxing — Adresse + Telefon → § 126a / § 238
  • victim_context-Regeln — Ex-Partner → § 238 Stalking

Kein silent fallback. Bei niedriger Confidence → 503. Eine schwache Regex-Klassifizierung wäre für eine Strafanzeige schlechter als keine.

class ClassificationResult(BaseModel): severity: Severity # low|medium|high|critical categories: list[Category] # enum, 16 Werte confidence: float # 0–1 requires_immediate_action: bool summary: str # EN summary_de: str # DE applicable_laws: list[GermanLaw] potential_consequences: str potential_consequences_de: str
client.chat.completions.parse( model="gpt-4o-mini", response_format=ClassificationResult, messages=[...])
SafeVoice · Klassifizierung 06 / 17
Zweiter KI-Layer

Vom Einzelbeleg zur Fallanalyse.

Ein zweiter Prompt-Pass fasst alle Belege + den vom Opfer beigesteuerten Kontext zu einer fallweiten juristischen Einschätzung zusammen. Das ist, was die Polizei lesen kann.

Was die KI ausgibt

  • Rechtliche Bewertung — Freitext-Absatz mit Begründung, DE + EN
  • Eskalationsrisiko — low / medium / high mit Begründung
  • Stärkste Vorwürfe — §§ mit Strength-Score
  • Nächste Schritte — priorisiert mit Deadlines (24 h / 7 d / when_ready)
Beispiel-Output · Case mit 4 Belegen

„Die Aussagen sind beleidigend und drohend, was sowohl nach § 185 StGB als auch § 241 StGB strafbar ist. Die Schwere der Drohung in der letzten Nachricht ist kritisch und erfordert sofortige Maßnahmen."

Eskalationsrisiko HIGH

„Die Drohung mit Gewalt könnte zu einer weiteren Eskalation führen."

Eingebettet im Strafanzeige-PDF mit klarem Disclaimer — typografisch abgesetzt, damit Polizist:in sofort erkennt: das ist die KI, nicht das Opfer.

SafeVoice · Zweiter KI-Layer 07 / 17
Iterationen & Learnings

Was wir verworfen haben, bis es funktionierte.

Sechs harte Pivots. Jeder davon war ein Eingeständnis: „die erste Idee war falsch."

Pivot 1 · Klassifizierung

Regex + Keyword-Liste + 3-Tier-Fallback
→ gpt-4o-mini mit Pydantic Structured Outputs

Warum: Regex hat „bringt mich um vor Lachen" als § 241 markiert. False-Positive-Rate war untragbar.

Pivot 2 · Modell-Auswahl

Claude (Anthropic) + OpenAI parallel
→ gpt-4o-mini only · one-provider stack

Tested: gpt-4o-mini vs gpt-4o vs gpt-5 (hyperparam-sweep). gpt-5 marginal besser bei Edge-Cases, aber 8× teurer + langsamer. gpt-4o-mini = beste Cost/Quality-Ratio.

Pivot 3 · Prompt-Engineering

Minimalist-Prompt (v1)
→ Few-Shot mit Chain-of-Thought (v2)

Eval (35 Cases): 66% → 86% Accuracy (+20 pp). Gegenbeispiele für Idiome, Obfuscation, victim_context dazugegeben.

Pivot 4 · UX-Architektur

Login-first · User-Konto · Email-Verifikation
→ Anonymous-first · localStorage · kein Konto

Warum: Opfer von Stalking sollen kein Konto eröffnen müssen, das später gegen sie verwendet wird. DSGVO-Datenminimierung. Konto = Bonus, nicht Pflicht.

Pivot 5 · Hosting

Railway · Docker · always-on
→ Vercel Functions · Fluid Compute · FRA

Effekt: $20/mo fix → $0–$3/mo at expected volume. Cold-Start < 200 ms via Fluid Compute. Eine Plattform = eine Rechnung.

Pivot 6 · OCR (heute beschlossen)

Tesseract + Vision-Fallback
→ Vision-only (gpt-4o-mini)

Warum: Auf Vercel lief Tesseract nie. Vision liefert sender_handle + platform_hint zusätzlich. Dev = Prod. 200 Zeilen Code weniger.

SafeVoice · Iterationen & Learnings 08 / 17
DB-Architektur · Vorher / Nachher

Vom User-zentrischen zum Fall-zentrischen Schema.

Der UX-Pivot „Anonymous-first" zwang einen DB-Pivot. user_id war nicht mehr Pflicht, sondern optional.

Vorher · Login-first (v1)

users id PK email UNIQUE NOT NULL password_hash created_at cases id PK user_id FK → users.id # required title context ... evidence id PK case_id FK → cases.id user_id FK → users.id # redundant ...

Problem: Opfer ohne Account = kein Case. Email-Verifikation als Barriere für jemand, der gerade in Krise ist. Doppelte FKs.

Heute · Anonymous-first (v2)

cases id PK user_id FK → users.id NULL # optional! anonymous_token UNIQUE # browser-local title, context, severity evidence id PK case_id FK text, image_bytes sha256_hash, archive_url classification_json # Pydantic SO legal_analysis # 2nd KI layer case_id FK assessment, escalation_risk applicable_laws users # nur für Power-Features id, email, password_hash

Heute 10 Tables. Cases können ohne User existieren — nur lokal im Browser. Login = optionaler Upgrade-Pfad für NGOs/Anwält:innen.

Beweissicherung

SHA-256. archive.org. Browser-Verifier.

Jeder Beleg bekommt einen SHA-256-Hash über den exakten Inhalt zum Erfassungszeitpunkt — ein 64-stelliger Fingerabdruck. Verändert sich ein einziges Zeichen, ändert sich der Hash komplett.

Zusätzlich:

  • UTC-Timestamp mit Zeitzone (juristisch erforderlich)
  • archive.org-Backup-Link (bei URL-Scrape)
  • Hash-Chain zwischen Belegen — Manipulation invalidiert die ganze Kette

NEU  Browser-Verifier. Polizei oder Anwält:in fügt den Originalinhalt ein, der Browser rechnet via Web Crypto API den Hash live — kein Vertrauen in unseren Server nötig.

// Im PDF sha256:3a11c1c3813f43e8d7b9dbda0dfbc571bd 362bf346c3d4412975d91475571c2a // In SafeVoice (Browser) const hash = await sha256Hex(originalText) // → derselbe Hash → unverändert ✓ // Im Terminal (jeder kann es) $ shasum -a 256 evidence.txt 3a11c1c3813f43e8d7b9d... // Drei-Wege-Verifikation. Police-grade.

SafeVoice · Tech & DSGVO 13 / 17
Warum LLM, warum jetzt

Warum funktioniert ein LLM, wo regelbasierte Systeme scheitern?

Was Sprache hier schwierig macht

  • Idiome — „Das bringt mich um vor Lachen" ist keine Bedrohung
  • Obfuscation — „H*re", „k!ll yourself", Leetspeak
  • Codes — 1488, 88, „14 words" — rechtsextremer Subtext
  • Kontext-Sensitivität — gleicher Satz: § 185 oder § 238 — je nach Sender
  • Mehrsprachigkeit — DE, EN, TR, AR im selben Fall

Wie wir es zuverlässig machen

  1. Schema enforcement — Pydantic Structured Outputs. Modell kann nichts erfinden.
  2. Few-Shot mit Gegenbeispielen — Idiome, Obfuscations, victim_context-Regeln
  3. Kein Silent-Fallback — 503 statt schwacher Regex
  4. Zweiter Layer für Fall-Ebene — kein Einzelbeleg trifft alleine die Entscheidung
  5. SHA-256 + Hash-Verifier — Polizei muss uns nicht vertrauen

FAQ · auch live auf safevoice.app/faq

Sechs Fragen, die uns immer wieder gestellt werden.

1 · Ist das ein rechtsverbindliches Beweismittel?

Das PDF selbst ist kein Urteil — es ist ein strukturiertes Anzeigedokument. Der SHA-256-Hash + archive.org-Backup + UTC-Zeitstempel machen den darunterliegenden Screenshot forensisch verifizierbar. Polizei und Staatsanwaltschaft können es direkt verwenden.

2 · Kann die KI einen falschen Paragraphen halluzinieren?

Nein. Die 16 Kategorien sind ein Pydantic-Enum, server-seitig durchgesetzt via OpenAI Structured Outputs. Das Modell kann keinen Wert außerhalb des Enums zurückgeben. Confidence-Werte unter 0.7 werden für menschliche Review markiert.

3 · Was passiert mit meinen Daten?

Anonymous-first: kein Account nötig, alles standardmäßig im Browser-localStorage. Server-seitig: nur was gerade verarbeitet wird (Vercel Functions Frankfurt, keine Logs des Inhalts). DSGVO Art. 25 by design.

4 · Warum Open Source?

Betroffene digitaler Gewalt sollten keiner Black Box vertrauen müssen. NGOs (HateAid, neue deutsche medienmacher*innen) müssen den Code auditieren und selbst hosten können. Und: Staatsanwält:innen können unsere Hash-Chain-Logik Zeile für Zeile prüfen.

5 · Was ist mit False Positives?

86 % Accuracy heißt: 14 % müssen geprüft werden. Das PDF zeigt immer Confidence + Begründung pro Klassifikation. Ein Mensch (Betroffene:r oder NGO) bestätigt vor der Einreichung. Wir ersetzen 4 Stunden Handarbeit, nicht das menschliche Urteil.

6 · Wer bezahlt das?

Kostenlos für Betroffene, dauerhaft. NGO-/Behörden-Pilots decken die Infra ($90/Monat bei 10k Fällen). Förderspur: Prototype Fund, Schöpflin, Bertelsmann. Ziel: Pilot mit HateAid in Q3 2026.

Auch veröffentlicht auf safevoice.app/faq — teilbar + pro Frage verlinkbar.
